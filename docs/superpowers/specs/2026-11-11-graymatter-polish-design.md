## 2. Цели, не-цели, анти-цели

### Цели
1. Приложение выглядит и ощущается как макет «Hybrid v2».
2. Частые действия с запасом не плодят записей и не блокируют всё приложение.
3. Повтор после сбоя сети не создаёт дублей. Медленная сеть не выглядит как её отсутствие.
4. Копию можно восстановить. О копии напоминают. Журнал защищён от случайной правки.
5. На вопрос «есть ли у меня?» отвечают список, быстрое добавление и «Поделиться», без лишних переходов.

### Не-цели
- П9: действия и быстрые команды в палитре.
- П4: свой адрес приложения и CI.
- Оставшаяся часть П5. П13: серии номиналов.
- Инструмент «слить предметы».
- Удаление файлов фото у провайдера (как и сейчас).
- S3-совместимое хранилище фото.
- Перевод интерфейса на русский.

### Анти-цели
1. **Оптимистичные обновления.** Основная спека 5.1 запрещает их по-прежнему. Ожидающее значение показывается как ожидающее, а подтверждённое число меняется только после ответа базы.
2. **Свой сервер, аккаунты, секреты вне устройства.**
3. **Запросы к базе по таймеру.** Neon должен засыпать.
4. **Цветные кнопки.** Цвет — только у акцентной кнопки, у выбранной строки и в лёгкой подсветке при наведении (решение владельца в Плане 3 остаётся).
5. **Контраст хуже 4.5:1** у текста и подписей. Неоморфизм не оправдывает бледный текст.
6. **Подтверждение для обратимого действия** (M). Отмена есть — значит подтверждение не нужно.

  - свет 1.2;
  - тень 0.7;
  - поверхность плоская;
  - акцентная кнопка закрашена;
  - акцент `#4F46E5`.
- **Акцентный цвет выбирается в настройках**, как палитра основного цвета в Nuxt UI.

## 4. Решения Claude

### 4.1 A. Стиль «Hybrid v2» **[решение Claude: перенос макета в токены]**

**Источник значений** — функция `hybrid2` в `project/ItemScreen.dc.html` макета. Ниже то, что переносится. Строитель берёт числа оттуда, если здесь их нет.

**Светлая тема.**

| Токен | Значение |
|---|---|
| фон | `#EDEFF3` |
| текст | `#1C2030` |
| приглушённый текст | `#565D6E` |
| иконки | `#2F3442` |
| разделитель | `#D9DDE5` |
| чип | `#DDE1E8` |
| подложка фото | `#E2E5EB` |
| граница шапки | `1px solid #DDE1E8` |

**Тени.** Выпуклость — пара теней:
- тёмная вниз-вправо: `rgba(150,160,180, 0.42·shade)`;
- светлая вверх-влево: `rgba(255,255,255, 0.8·light)`.

Смещение и размытие масштабируются глубиной, светом и тенью, как в `sh()` макета. При `depth = 0.9`, `light = 1.2`, `shade = 0.7` значения вычисляются один раз и записываются числами в CSS. Ползунков в приложении нет.

**Что выпуклое:**

| Элемент | Тень | Радиус |
|---|---|---|
| иконочная кнопка | R(3, 7) | 14 px |
| кнопка «Add…» | R(3, 7) | 14 px |
| обычная кнопка | R(4, 10) | 14 px |
| пилюля степпера | R(3, 8) | 14 px |
| карточка (запас, фото-блок) | R(6, 14), внутренний отступ 18 px | 20 px |

**Что плоское:**
- Списки лежат прямо на фоне, строки разделены `1px #D9DDE5`. Так длинный список не превращается в стопку подушек.
- Шапка плоская, с нижней границей.

**Состояния:**
- **Наведение.** Цвет тянется к акценту (`mix(фон, акцент, 0.06–0.07)`), тёмная тень тоже получает оттенок акцента. Элемент не двигается.
- **Нажатие.** Тени уходят внутрь (`inset`), элемент уменьшается до `scale(0.97)` (кнопки — `0.985`), фон — `mix(фон, акцент, 0.11–0.12)`. Переходы: фон и цвет — 180 мс, тень — 200 мс, трансформация — 120 мс. Выпуклая и вдавленная пары теней перечисляются всегда, неиспользуемая — нулями, чтобы переход анимировался, а не прыгал.
- **Выбранная строка** (папка в дереве, строка палитры, текущий вариант): градиент `90deg` от `акцент/0.17` к `акцент/0.08`. Текст — `mix(акцент, чёрный, 0.18)`. Радиус 14 px.
- **Акцентная кнопка** закрашена акцентом, текст белый. Скос — внутренняя светлая кромка сверху-слева и тёмная снизу-справа. При нажатии вдавливается так же, как остальные.
- **Фокус с клавиатуры:** видимое кольцо `2px` цвета акцента со смещением 2 px. Одной тени для фокуса мало.
- **`prefers-reduced-motion`:** без масштабирования и анимаций теней.

**Тёмная тема** [решение Claude: в макете есть только тёмный «Dark classic»] — та же структура «Hybrid» на палитре «Dark classic»:

| Токен | Значение |
|---|---|
| фон | `#24272E` |
| текст | `#E7E9EE` |
| приглушённый текст | `#A0A6B3` |
| иконки | `#D4D8E0` |
| тёмная тень | `rgba(0,0,0,0.55)` |
| светлая тень | `rgba(255,255,255,0.06)` |
| разделитель | `rgba(255,255,255,0.06)` |

Текст выбранной строки — светлый вариант акцента (`mix(акцент, белый, 0.55)`). Каждая пара «текст/фон» должна давать контраст ≥ 4.5:1. Если не даёт, оттенок подбирается, а не принимается.

**Как устроено в коде:**
- Токены лежат в `packages/app/app/assets/css/main.css` на `:root` и в тёмной теме.
- Общие классы или утилиты Tailwind (`raised`, `raised-sm`, `pressable`, `selected-row` — имена выбирает строитель) применяются в примитивах `components/ui/*` и в компонентах приложения.
- Шрифт не меняется, Manrope из макета не берём [решение Claude].

**Выбор акцента** — Настройки → Appearance → Accent, круглые образцы. Набор [решение Claude, по образцу Nuxt UI, только цвета с белым текстом на закраске ≥ 4.5:1]:

|---|---|---|
| indigo | `#4F46E5` | по умолчанию |
| violet | `#7C3AED` | |
| blue | `#2563EB` | |
| sky | `#0369A1` | |
| teal | `#0F766E` | |
| green | `#15803D` | |
| orange | `#C2410C` | |
| rose | `#BE123C` | |
| pink | `#BE185D` | |

- Хранится в настройках устройства (`DeviceSettings.accent`) и применяется переменной `--accent` на `:root` до первого кадра, чтобы не мигало.
- Неизвестное значение (от более новой версии) считается неустановленным.

### 4.2 B. Правки интерфейса
- **Курсор-указатель** у всего, на что можно нажать: кнопки, строки-ссылки, пункты меню, иконочные кнопки, «+ Add tag», «⋯». Правило ставится в базовые стили (`button:not(:disabled), [role=button], a[href], summary { cursor: pointer }`) и проверяется тестом по всем `.vue`. Недоступные элементы — `cursor: default`.
- **Радиусы — шкала из 4 значений:**
  - 20 px — карточки и шторки;
  - 14 px — кнопки, поля, строки-плитки, выбранная строка;
  - 10 px — чипы и вложенные элементы внутри карточек;
  - круг — аватар и образец цвета.

  Вложенный элемент не может быть круглее родителя: радиус вложенного ≤ радиус родителя − отступ между ними. Это касается и строк папок в «Add item», и кнопок внутри карточек. Строитель проходит все компоненты.
- **Выбранная строка палитры** использует правило «выбранная строка» из 4.1. Тёмно-фиолетовая подложка с тёмно-серой иконкой исчезает, иконка выбранной строки — цвета текста строки.
- **Кнопка инвентаря в боковом меню** при наведении получает подсветку из 4.1. Сейчас она сливается с фоном.

### 4.3 C. Дерево папок
- **Клик по строке папки:**
  - если папка не текущая — переход к ней (выбор), раскрытие не меняется;
  - если уже текущая — раскрыть или свернуть.

  Стрелка-шеврон по-прежнему раскрывает и сворачивает сразу. На телефоне в выдвижном меню — то же самое.
- **Числа** (решение владельца, §8, вопрос 1).
  - Число у папки — в дереве, в строке папки списка и у корня инвентаря — это сумма запаса в поддереве **только по предметам в штуках**. Раньше там было количество предметов (`TreeNode.itemCount`), теперь его нет.
  - Предметы в метрах, граммах и своих единицах в сумму не входят. Архивные предметы и варианты не считаются.
  - Папка, где нет предметов в штуках, числа не показывает.
  - Сумма показывается по правилам штук, с приставками `k` и `M` (E): `1.2k`.
  - Строка предмета в списке показывает запас с единицей суффиксом: «5» для штук без суффикса, «3 m», «2 kg» — единица на шаг мельче и приглушённая. Приставки — по правилам единицы (`1.5k` для 1500 шт после E).
- **Ширина дерева на компьютере.**
  - Правый край панели тянется мышью.
  - Ширина от 200 px до 50 % окна.
  - Двойной клик по краю — ширина по умолчанию.
  - Хранится в `localStorage` (`gm.treeWidth`, в пикселях), каждое чтение и запись — в `try/catch`.
  - С клавиатуры: край — фокусируемый разделитель с `role="separator"` и `aria-orientation="vertical"`, стрелки меняют ширину на 16 px.

### 4.4 D. Шторки
- **Полное описание.**
  - Во всех шторках о предмете или варианте под заголовком стоит строка описания: подпись варианта, имя предмета, затем значения общих атрибутов в порядке показа, не больше трёх, через « · ». Например: «10 kΩ · Резистор 0,25 Вт · 5 %».
  - Это шторки Receive, Use, Count, Transfer, Edit variant, Photo, Archive и Delete.
  - Строку строит одна функция [решение Claude: `bucketDescription(snapshot, itemId, variantId)` в `lib/item-view.ts`].
- **Ctrl+Enter, а на Mac ⌘+Enter,** в любой шторке и модалке нажимает основную кнопку, если она доступна. Внутри многострочного поля обычный Enter переносит строку, Ctrl/⌘+Enter отправляет. Делается один раз в `AppSheet`: шторка получает ссылку на свою форму или основное действие.
- **«New folder»** получает выбор родителя — тот же список-выбор папки, что в «Add item». По умолчанию — текущая папка, в корне — корень.

### 4.5 E. Единицы
- В «New unit» и «Edit unit» каждая приставка подписана: символ · имя · степень, например «Y · yotta (10^24)», «µ · micro (10^-6)». В Tags & fields у единицы тоже показываются её приставки.
- У встроенной единицы «штуки» (`pcs`) появляются приставки `k` (10³) и `M` (10⁶): `BUILTIN_UNITS.pcs.prefixPowers = [3, 6]`. Ввод «1.5k» в поле количества даёт 1500. Показ крупных чисел — по общим правилам `formatAmountParts`. В разделе единиц Tags & fields у штук приставки видны так же, как у метров.

### 4.6 F. Несколько хранилищ фото
- **Хранилище фото** выбирается в настройках источника (или файлового хранилища, где оно сейчас задаётся — строитель найдёт по коду Uploadcare):
  - **Uploadcare** — как сейчас;
  - **Cloudinary** — `cloud name` и `unsigned upload preset`, загрузка без секрета через `https://api.cloudinary.com/v1_1/<cloud>/image/upload`. Миниатюры — преобразования в адресе (`/upload/w_400,c_limit/…`);
  - **Imgur** — `Client-ID`, анонимная загрузка `POST https://api.imgur.com/3/image`. Миниатюры — суффиксом размера (`…m.jpg`, `…l.jpg`).
- **Новые пакеты** `packages/files-cloudinary` и `packages/files-imgur` реализуют интерфейс `FileStore` из `packages/core/src/files.ts`. Коды ошибок: `rejected`, `too_large`, `unavailable`, `failed`.
- **Адрес миниатюры** строит функция по `provider` (сейчас `photoUrl`).
- **Уже загруженные фото** остаются у своего провайдера и показываются по своему `provider`.
- **Ключи** — только на устройстве, как ключ Uploadcare. Для каждого провайдера — ссылка «как получить ключ».
- **CSP** (`packages/app/app/lib/csp.ts`, тест `csp.test.ts`): `img-src` дополняется `https://res.cloudinary.com` и `https://i.imgur.com`, `connect-src` — `https://api.cloudinary.com` и `https://api.imgur.com`. `nuxt.config.ts` для этого не трогается.

### 4.7 G. Повтор без дублей и честное состояние сети (П2)
- **Стабильные id.**
  - `composables/useCommandIds.ts`: `useCommandIds<K extends string>(keys: readonly K[]): { ids: Readonly<Record<K, Id>>; renew(): void }`.
  - Id создаются при открытии формы, обновляются только после успеха или при закрытии.
  - Сборщики команд (`buildQuickAdd`, `buildStockCommand`, `quickStep` и подобные) получают id параметрами.
  - Касается всех форм создания и диалогов архивации (`archiveId` — один на открытие).
  - Повторный «Save» после таймаута отправляет ту же команду. База пропускает её молча (`on conflict do nothing` уже есть), а ядро не должно отклонять повтор своей же команды.
  - Правило Плана 7 «`variant.createMany` отклоняет существующие id» меняется: id, который уже принадлежит варианту того же предмета с теми же значениями, — это повтор, а не ошибка.
- **Раздельные таймауты Neon:**
  - запись — 15 с до первого байта ответа;
  - чтение снимка — 90 с всего, медленное скачивание тела не считается обрывом.
- **Исчерпанный лимит Neon** распознаётся по ответу Neon при приостановленном проекте; строитель определяет признак по документации Neon и реальному ответу. Тогда источник получает состояние `quota`: баннер «Monthly Neon limit reached. Read-only until <date>. Export a backup» с кнопкой экспорта. Если надёжного признака нет, состояние `quota` не делается, а в отчёте пишется почему [решение Claude]: ложный баннер хуже его отсутствия.
- **Журнал ошибок на устройстве.**
  - Последние 200 ошибок: время, место, код, текст.
  - Без строк подключения, ключей и паролей: фильтр по шаблонам `postgres(ql)?://…` и значениям ключей из настроек.
  - Настройки → Diagnostics → Copy и Share.
- **Прогрев.** При открытии быстрого добавления или формы запаса, если база не отвечала больше 4 минут, приложение делает один лёгкий запрос (`listInventories` или `select 1`). По таймеру — никогда.
- **Счётчик трафика.** Оценка байтов ответов Neon за календарный месяц на этом устройстве: «~120 MB of 5 GB this month (this device)» в карточке источника. Это оценка.

### 4.8 H. Восстановление, напоминание, защита журнала, мягкие миграции (П3)
- **Восстановление** — Настройки → источник → «Restore from backup…».
  - Файл копии (формат текущего экспорта, `lib/backup.ts`) разбирается и показывается сводкой: инвентари, предметы, движения, дата экспорта.
  - Два режима:
    - **в пустой источник с теми же id** — после аварии;
    - **как новые инвентари с новыми id** — когда в источнике уже есть данные.
  - Пишется пакетами по ~500 строк (`unnest`, `on conflict do nothing`), с индикатором хода. Прерванное восстановление запускается снова.
  - **Новые id детерминированы** [решение Claude]. Новый id — UUID v5 от старого id в пространстве имён «запуска восстановления». Id запуска хранится на устройстве по отпечатку файла копии (sha-256), поэтому повторный запуск с тем же файлом получает те же новые id, и `on conflict do nothing` убирает дубли. Переназначаются все ссылки: каждая uuid-колонка схемы, указывающая на другую строку (папки, предметы, варианты, теги, атрибуты, свои единицы и `unitKey` вида `custom:<id>`, связи атрибутов и тегов, движения и их `transferId`, фото, `archiveId`). Список берётся из схемы, а тест проверяет, что после восстановления в новом режиме ни одна ссылка не указывает на старый id.
  - Копия более новой схемы не восстанавливается: «made by a newer GrayMatter».
  - Новая операция хранилища: `restore(backup, mode, onProgress)` [решение Claude: имя и форма — строителю].
- **Напоминание.**
  - В настройках источника строка «Last backup: 12 days ago».
  - Один тихий тост за сессию, если прошло больше 14 дней или больше 200 записей с последней копии.
  - Дата и счётчик — на устройстве.
- **Экспорт на Android** — через `navigator.share({ files })` (Drive, Telegram). Если не получилось — обычное скачивание.
- **Защита журнала.** Триггер запрещает `UPDATE` строк `movements` [решение Claude: только `UPDATE`]. `DELETE` не трогаем: движения удаляются каскадом при окончательном удалении предмета, варианта или инвентаря, и запрет удаления пришлось бы обходить в этих путях. Код приложения нигде не меняет и не удаляет движения напрямую (проверено поиском по `storage-postgres/src`). Восстановление только вставляет, триггер ему не мешает.
- **Мягкие миграции.**
  - `gm_meta.min_app_schema` — минимальная версия приложения, которой можно писать.
  - Добавляющие миграции его не поднимают. Приложение уходит в «только чтение», только если `min_app_schema` больше его `APP_SCHEMA_VERSION`.
  - Если приложение всё-таки только читает из-за новой схемы, `registration.update()` и баннер «Update to keep editing».
- **Миграция `0001`** (схема 4): триггер журнала, `min_app_schema = 3`, `attributes.pinned` (K). Её пролог берёт блокировку строки ревизии (`LOCK_REV`): это перенос из Плана 6, и он обязателен для первой настоящей миграции.

### 4.9 I. «Это у вас уже есть» (П6)
- Пока вводится имя в быстром добавлении (задержка 150 мс), под полем показываются до 3 совпадений: «NE5532P · Op-amps · 4 pcs» и кнопка «Receive here».
- **Совпадения:** точные и по префиксу, без нечёткого поиска; префикс номера детали (`TL072` ↔ `TL072CP`); числовые значения по правилам атрибутов (План 7).
- **Касание «Receive here»** переключает шторку в приёмку этого предмета (или варианта). Введённые количество, цена и ссылка сохраняются.
- «Save» никогда не блокируется.

### 4.10 J. «Поделиться» и вставка ссылки (П7)
- **PWA — цель «Поделиться».** В манифест добавляется `share_target` методом GET на маршрут `share` относительно `baseURL` приложения (на GitHub Pages — `/graymatter/share`) с параметрами `title`, `text`, `url`. На Android ссылка приходит внутри `text`. Свой service worker не нужен. Холодный старт по этому адресу работает так же, как любая глубокая ссылка сейчас (`404.html` и `navigateFallback`). Проверить настоящее «Поделиться» можно только на развёрнутой PWA. До того — тесты разбора и маршрута, а `/share?text=…` открывается вручную.
- **Шторка `/share`:**
  - очищенный запрос и до 5 лучших совпадений с запасом;
  - номинал-чипы из заголовка: каждое слово разбирается по правилам числовых атрибутов инвентаря, как в поиске Плана 7. «10K ✓ 120» — есть, «47K — нет»;
  - если ссылка совпала с прошлым получением по ключу лота: «Bought on 12 Aug: 100 pcs · 37 left»;
  - кнопки «Open», «Receive…» (ссылка подставлена), «Quick add» (имя и ссылка подставлены).
- **Очистка заголовка** убирает количества лота (`600PCS`, `Lot of 10`), рекламные слова (`Free shipping`, `New`, `Original`), знаки и скобки. Шумовые слова — список в коде с тестами [решение Claude].
- **Ключ лота** — id товара из адреса AliExpress (`/item/<digits>.html`). Для других магазинов — нормализованный адрес без параметров. Совпадение ищется по `movements.source_url` новой операцией хранилища `findReceiptsBySource(inventoryId, key)`: она возвращает дату, количество, предмет и вариант. Короткие ссылки `a.aliexpress.com/_…` не раскрываются (CORS), для них работает поиск по заголовку.
- **На компьютере** вставка ссылки или длинного заголовка в палитру (⌘K) открывает ту же шторку.
- **«Find in shops»** в карточке предмета: ссылки поиска по имени предмета на LCSC, AliExpress, Mouser, Tayda, Thonk, Octopart. Только ссылки, без API.

### 4.11 K. Списки, которые отвечают сразу (П8)
- **Строка предмета с вариантами** показывает корзины: «1 kΩ 3 · 10 kΩ 100 · 100 kΩ —». Не больше 4 корзин, дальше «+N», в порядке вариантов. Корзина «без варианта» — только если в ней не ноль. Нулевой запас — тихая плашка «Out».
- **Монограмма** у предметов без фото вместо одинаковой иконки: первые буквы двух первых слов или две первые буквы («TL», «NE», «Рз»). Фото её заменяет.
- **Закреплённый атрибут.**
  - Флаг «Show in lists» у атрибута, не больше двух на инвентарь (ошибка `too_many_pinned`).
  - Значение — приглушённым чипом в строке списка, в палитре и в шапке карточки предмета: «B4», «DIP-8».
  - Числовые значения — в формате атрибута.
  - Хранится в `attributes.pinned` (миграция в 4.8). Команда `attribute.update` получает `pinned?: boolean`.

### 4.12 L. Степпер с отложенной записью и карточка запаса (П11)
- **Отложенная дельта.**
  - Нажатия «+» и «−» по одной корзине копятся в чип «+3 → 48» с кольцом обратного отсчёта.
  - Через 2 с после последнего нажатия уходит одно движение на сумму (`stock.receive` или `stock.use`; при нуле — ничего).
  - «Undo» на чипе до отправки отменяет всё, и в базу ничего не пишется.
  - Отправка раньше срока — при уходе со страницы, при `visibilitychange: hidden`, перед любой другой записью и при закрытии карточки.
  - Подтверждённое число меняется только после ответа базы (анти-цель 1).
  - Если «−» уводит ожидание ниже нуля, кнопка «−» перестаёт работать (`insufficient_stock` заранее).
- **Сбой отправки.** Чип остаётся с ожидающей дельтой, становится красным по тексту (не по фону) и показывает «Retry» и «Discard». Если вкладку закрыли или убили посреди отправки, ожидающая дельта теряется. На устройстве она не сохраняется [решение Claude]: окно не больше 2 секунд, а следующий запуск честно показывает число из базы.
- **Блокировка — только той корзины,** в которую идёт запись. Остальное приложение не становится серым. Общий `locked = readOnly || saving` для степперов заменяется блокировкой по корзине. Формы и шторки по-прежнему ждут свою запись.
- **Карточка запаса:**
  - большое число слева, одна пилюля [− | +] справа, зоны по 44 px;
  - второй ряд — «Receive · Use · Count»;
  - под числом: «avg $0.054 ea · last $0.025».
- **Касание числа** (на карточке и в строке варианта) открывает «Count» с текущим количеством, выделенным для замены.
- **Строки вариантов:** пилюля `[− 100 pcs +]`, подпись варианта до двух строк.
- **Отклик:** 8 мс вибрации на каждое нажатие степпера (`navigator.vibrate`, где есть).

### 4.13 M. Архив сразу, с «Undo» (П12)
- Архивация предмета, папки или варианта выполняется сразу, без `ConfirmSheet`.
- Тост «“NE555” archived · Undo»:
  - висит не меньше 6 с и замирает, пока на него наведён указатель или палец;
  - «Undo» отправляет `{ type: 'restore', archiveId }`;
  - на компьютере, пока тост виден, работает и Ctrl/⌘+Z;
  - тост переживает переход: архивация из карточки возвращает в папку.
- `ConfirmSheet` остаётся только для необратимого:
  - удаление насовсем;
  - удаление тегов, атрибутов и единиц;
  - удаление атрибута или оси, у которых пропадут значения (План 7);
  - архивация целого инвентаря.

### 4.14 N. Пересчёт, который оставляет след (П14)
- **`stock.set` пишет всегда.** При совпадении — `adjustment` на 0, в том числе для пустой корзины («Counted: 0 ✓»). В журнале такая строка читается как «Counted: 37 ✓». Схема не меняется: у `movements` есть только проверка вида, ограничения на ненулевое количество нет (проверено). Условие `having … <> 0` в `storage-postgres/src/commands/stock.ts` убирается. Повтор той же команды с тем же `movementId` не пишет вторую строку (`on conflict do nothing`).
- **«Counted 3 weeks ago»** — приглушённо на карточке запаса, по последнему `adjustment` этой корзины: новое поле `StockLine.lastCountedAt: string | null` в агрегате запаса.
- **«Count this folder»** в меню папки:
  - список предметов и вариантов папки (без подпапок) с числовыми полями, заполненными текущим запасом;
  - изменённые строки помечены;
  - липкая полоса «Apply 7 changes» отправляет `stock.set` по очереди с прогрессом, со стабильными id (4.7);
  - сбой посередине оставляет уже записанное и показывает, что не записалось.
- **История:**
  - группы по дням: Today, Yesterday, Nov 10;
  - в строке только время;
  - количество со знаком;
  - тихий бегущий остаток «→ 45».

## 5. Ограничения
- Всё остаётся на ветке `revival`. Никаких push, PR и Pages. Никаких строк атрибуции в коммитах.
- Только pnpm. Легаси `api/` и `web/` не трогаются. Строки подключения и ключи не печатаются и не коммитятся. Neon в тестах — только база `_test` через `GM_NEON_TEST_URL`.
- **Правила записи Плана 6** обязательны для каждой новой и изменённой команды и для восстановления. Восстановление — широкая операция: после неё устройства перезагружаются.
- **Схема 4** — одна миграция `0001` поверх начальной миграции схемы 3. `SCHEMA_BASE` не меняется.
- **Новые внешние адреса** (Cloudinary, Imgur) добавляются в CSP явно. Других внешних запросов нет.
- **Проверки в браузере** — только общая картина: два снимка на задачу с интерфейсом, 1280 px и 360 px.

## 6. Приёмка
1. **Стиль.** Экран предмета на 1280 и 360 px совпадает по характеру с доской «Hybrid v2»: выпуклые кнопки и карточки, плоские списки, подсветка цветом при наведении, вдавливание при нажатии. Тёмная тема — та же структура. Контраст текста везде ≥ 4.5:1.
2. **Акцент.** Выбор в настройках сразу перекрашивает акцентную кнопку, выбранные строки и подсветку. После перезапуска выбор сохраняется.
3. **Курсор.** Тест находит все кликабельные элементы без `cursor: pointer`. Таких нет.
4. **Дерево.**
   - Первый клик по папке выбирает её, второй сворачивает.
   - Сумма у папки учитывает только штуки.
   - Ширина тянется, не больше половины окна и не меньше 200 px, и переживает перезагрузку.
5. **Шторки.** Шторка «Use» варианта показывает «10 kΩ · Резистор 0,25 Вт · …». Ctrl+Enter отправляет любую шторку.
6. **Новая папка.** «New folder» создаёт папку в выбранном родителе.
7. **Единицы.** В «New unit» у приставок есть пояснения. «1.5k» в поле количества у штук даёт 1500.
8. **Фото.** С Cloudinary и с Imgur фото загружается и показывается миниатюрой. Старые фото Uploadcare показываются по-прежнему.
9. **Без дублей.** Повторный «Save» быстрого добавления после искусственного таймаута не создаёт второй предмет. Тест — на уровне сборщика команд и хранилища.
10. **Сеть.** Медленное чтение снимка дольше 20 с, но короче 90 с не даёт «offline». Журнал ошибок не содержит строки подключения.
11. **Восстановление.**
    - Копия восстанавливается в пустой источник с теми же id.
    - Копия восстанавливается как новые инвентари рядом с существующими.
    - Повторный запуск после обрыва не создаёт дублей.
12. **Журнал защищён.** `UPDATE movements` в базе отклоняется.
13. **Миграция.** Приложение схемы 4 открывает базу схемы 3 и мигрирует её. Приложение схемы 3 на базе схемы 4 с `min_app_schema = 3` может писать.
14. **«Уже есть».** Ввод «ne5532» в быстром добавлении показывает `NE5532P` с запасом. «Receive here» переносит введённые количество и цену.
15. **«Поделиться».** Заголовок AliExpress с «10K 4.7K 47K» даёт чипы по наличию. Ссылка на уже купленный лот показывает «Bought on …».
16. **Списки.** Строка резистора показывает корзины по номиналам, предмет без фото — монограмму, закреплённый атрибут — чипом.
17. **Степпер.** Пять быстрых «+» дают одну запись на 5. «Undo» до отправки не пишет ничего. Во время записи остальные кнопки приложения доступны.
18. **Количество по касанию.** Касание числа открывает «Count».
19. **Архив.** Архивация — без подтверждения, «Undo» в тосте восстанавливает.
20. **Пересчёт.** Совпавший пересчёт пишет «Counted: 37 ✓», карточка показывает «Counted … ago». «Count this folder» применяет изменения по очереди.
21. **Проверки.** `pnpm test`, `pnpm typecheck` и `pnpm lint` зелёные. Набор соответствия на Neon зелёный.
